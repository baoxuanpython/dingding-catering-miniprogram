## 一、技术栈总览

| 决策项    | 选择                          | 说明                                |
| --------- | ----------------------------- | ----------------------------------- |
| 框架      | **原生微信小程序**            | Skyline 渲染 + glass-easel 组件框架 |
| 语言      | **TypeScript（strict 模式）** | 全局迁移，不与 JS 共存              |
| UI 库     | **WeUI** (npm 安装)           | 微信官方组件库，按需引入            |
| 状态管理  | **app.globalData**            | 轻量级，适合用户端规模              |
| HTTP 封装 | **自定义 request.ts**         | 统一处理 token、错误码、401 跳转    |
| CSS 方案  | **WXSS + WeUI**               | 不用预处理器                        |

## 四、核心业务流程

### 4.1 登录流程

```
用户打开小程序
  ↓
app.ts onLaunch 触发
  ↓
调用 wx.login() 获取微信授权码 code
  ↓
POST /user/user/login { code }
  ↓
后端返回 token + 用户信息（name/avatar 可能为空）
  ↓
保存 token 到 globalData + Storage
  ↓
判断 name 或 avatar 是否为空？
  ├─ 是 → 弹出微信授权弹窗（chooseAvatar + nickname input）
  │       → 用户允许后调用 PUT /user/user/info 完善信息
  └─ 否 → 直接进入首页
```

**关键点：**

- 使用 `<button open-type="chooseAvatar">` 获取头像
- 使用 `<input type="nickname">` 获取昵称
- 完善信息是**可选操作**，不强制

### 4.2 浏览下单流程（核心链路）

```
首页（左右分栏）
  ↓ 点击分类
右侧加载对应菜品/套餐列表
  ↓ 点击某个菜品/套餐
进入菜品/套餐详情页
  ↓ 选择口味 + 数量
点击"加入购物车"
  ↓ POST /user/shoppingCart/add
首页底部迷你购物车条更新（数量+金额）
  ↓ 点击迷你购物车条
弹出上拉框（当前已选商品列表）
  ↓ 或点击"去结算"
跳转购物车 Tab 页
  ↓ 确认商品 + 选择地址
点击"结算"
  ↓
跳转提交订单页
  ↓ 选择地址 + 支付方式 + 备注 + 打包费/餐具
点击"提交订单"
  ↓ POST /user/order/submit
弹出支付弹窗（模拟支付）
  ↓ PUT /user/order/payment
显示"支付成功"
  ↓
跳转订单详情页
```

### 4.3 购物车数据流

```
加购操作
  ↓
本地更新 globalData.cartList（立即响应）
  ↓ 异步
调用后端 API 同步
  ↓
成功 → 保持本地数据
失败 → 回滚本地数据 + 提示错误

每次进入首页/购物车页
  ↓
优先使用 globalData 缓存
  ↓ 同时请求 GET /user/shoppingCart/list
  ↓
成功 → 更新缓存
失败 → 使用缓存（容错）
```

## 五、接口对接规范

### 5.1 基础配置

```typescript
// utils/env.ts
export const ENV = {
  BASE_URL: "http://localhost:8080", // 开发环境
  // 上线时改为生产地址
};
```

### 5.2 请求封装要求

**request.ts 必须实现：**

1. **Token 注入**：自动从 `globalData.token` / `Storage` 读取并添加到 Header `token` 字段
2. **统一错误处理**：
   - HTTP 400 → `wx.showToast({ title: '参数错误' })`
   - HTTP 401 → 清除 token → 跳转首页触发重新登录
   - HTTP 403 → `wx.showToast({ title: '无权限' })`
   - HTTP 409 / 422 → 解析 `msg` 字段提示用户
   - HTTP 500 → `wx.showToast({ title: '系统异常' })`
3. **业务错误码映射**：
   - 1001-1004：认证失败 → 同 401 处理
   - 6001-6003：订单业务错误 → 显示具体 msg
   - 7001-7002：购物车业务错误 → 显示具体 msg
   - 8001-8002：地址业务错误 → 显示具体 msg
   - 99001：参数校验失败 → 显示具体 msg
   - 99999：未知错误 → "系统繁忙，请稍后再试"
4. **Loading 状态**：支持传入 `showLoading` 参数控制是否显示 loading
5. **TypeScript 泛型**：`request<T>(options): Promise<ApiResponse<T>>`

### 5.3 接口文档强制对齐

**绝对禁止的行为：**

- ❌ 凭空捏造接口字段名
- ❌ 猜测字段类型（必须以接口文档的 TypeScript interface 为准）
- ❌ 省略必填字段
- ❌ 添加接口文档中不存在的字段

**正确做法：**

- ✅ 所有 DTO 参数必须从 `types/*.d.ts` 导入
- ✅ 所有响应数据必须用对应的 VO 类型接收
- ✅ 字段名大小写严格遵循接口文档（如 `orderDishes` 不是 `order_dishes`）
- ✅ 如果接口文档有歧义或矛盾，先问用户再写代码

## 六、UI/UX 规范

### 6.1 错误提示分级

| 级别         | 场景                           | 组件           | 示例                   |
| ------------ | ------------------------------ | -------------- | ---------------------- |
| **关键操作** | 取消订单、删除地址、清空购物车 | `wx.showModal` | "确定要取消该订单吗？" |

- **左侧**：固定宽度分类列表（可滚动），选中高亮

- **底部**：固定迷你购物车条（显示数量和总价）
  - 点击 → 从底部滑入上拉框（sheet）
  - 上拉框内容：已选商品列表 + 数量调整 + "去结算"按钮

### 6.3 TabBar 配置

- **纯文字模式**（暂无图标）
- 4 个 Tab：首页 / 购物车 / 订单 / 我的
- 颜色：默认灰色，选中色主题色（待定）

### 6.4 地址选择器

使用微信内置 `<picker mode="region">`，不做自定义。

## 七、特殊功能说明

### 7.1 文件上传（头像）

- **接口**：`POST /admin/common/upload`（multipart/form-data）
- **流程**：`wx.chooseImage()` → `wx.uploadFile()` → 返回 OSS URL → 调用 `PUT /user/user/info` 保存
- **注意**：这是管理端接口，但用户端可用

### 7.2 模拟支付

- **接口**：`PUT /user/order/payment`
- **UI 流程**：调用接口 → 弹出自定义 modal "支付成功" → 用户点击确定 → 跳转订单详情
- **注意**：不调用真实支付 API，个人开发者限制

### 7.3 订单状态流转

```
1(待付款) → 2(待接单) → 3(已接单) → 4(派送中) → 5(已完成)
                ↘
                  6(已取消) ← 用户取消（状态=1或2时）
                  7(已退款) ← 用户取消且已支付
```

**用户可执行操作：**

- 状态 1/2：取消订单
- 状态 2-4：催单
- 状态 5/6/7：再来一单（重新加入购物车）

## 九、代码风格约束

### 9.1 文件命名

- 页面文件：`index.ts` / `index.wxml` / `index.wxss` / `index.json`
- 组件文件：同上，放在 `components/组件名/` 下
- 类型文件：`模块名.d.ts`（如 `order.d.ts`）
- 工具文件：`功能名.ts`（如 `request.ts`）

### 9.2 代码组织

每个 Page 文件的标准结构：

```typescript
// pages/xxx/index.ts
import { xxx } from "../../types/xxx";
import { request } from "../../utils/request";

Page({
  data: {
    // 页面状态数据
  },

  onLoad(options) {
    // 初始化
  },

  // 业务方法...

  // 私有方法以 _ 开头
  _privateMethod() {},
});
```

### 9.3 注释规范

- 公共方法必须有 Javadoc 风格注释
- 关键业务逻辑必须注释说明原因
- 不要注释显而易见的代码

### 9.4 禁止事项

- ❌ 使用 `any` 类型（除非实在无法推断，需注释说明原因）
- ❌ 魔法数字/字符串（必须提取为常量或枚举）
- ❌ 硬编码的 URL 或配置（必须放 env.ts）
- ❌ 直接修改 props 或全局状态的深层对象（必须 immutable 更新）
- ❌ 在 WXML 中写复杂逻辑（必须移到 JS 中计算好再渲染）

## 十、质量保证

### 10.1 每次改代码前必须

1. 说明要改什么文件
2. 为什么改
3. 影响范围（哪些页面/组件会受影响）

### 10.2 不做的事

- 不过度优化（先跑通再打磨）
- 不改动已有文件的结构（除非明确讨论并同意）
- 不做"过度抽象"（如果只有一处用到，不要抽成通用函数）

### 10.3 测试策略

- 手动测试为主（微信开发者工具真机调试）
- 每完成一个 Phase 后进行一次完整流程测试
- 重点测试边界情况：
  - 未登录状态下访问需要认证的页面
  - 购物车为空时点击结算
  - 订单状态不允许的操作（如已完成订单尝试取消）
  - 网络异常时的降级处理
