## 通用说明

### 基础路径

```markdown
Base URL: /user
```

### 统一响应格式

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": {}
}
```

| 字段   | 类型     | 说明                                     |
| ------ | -------- | ---------------------------------------- |
| `code` | `number` | 状态码：`1`=成功，其他=失败              |
| `msg`  | `string` | 提示信息                                 |
| `data` | `any`    | 响应数据，类型因接口而异                 |

### 统一分页响应格式

```json
{
  "code": 1,
  "msg": "操作成功",
  "data": {
    "total": 100,
    "records": []
  }
}
```

| 字段      | 类型     | 说明           |
| --------- | -------- | -------------- |
| `total`   | `number` | 总记录数       |
| `records` | `array`  | 当前页数据列表 |

### HTTP 状态码说明

| HTTP 状态码 | 含义                                   | 前端处理建议             |
| ----------- | -------------------------------------- | ------------------------ |
| `200`       | 请求成功                               | 正常处理响应数据         |
| `400`       | 参数校验失败                           | 提示用户检查输入         |
| `401`       | 认证失败（未登录/令牌过期）            | 跳转登录页               |
| `403`       | 权限不足                               | 提示用户无权操作         |
| `409`       | 资源冲突                               | 提示用户具体冲突原因     |
| `422`       | 业务规则不满足                         | 提示用户具体业务错误     |
| `500`       | 服务器内部错误                         | 提示系统异常，联系管理员 |

### 认证方式

- 用户通过微信授权登录，返回 JWT token
- 后续请求需在 Header 中携带 token（Header 名称：`token`）

### 业务错误码说明

| ------ | ------------------------ | ---------------- |
| `1001` | 令牌已过期               | 401              |
| `1002` | 令牌无效                 | 401              |
| `1003` | 用户未登录               | 401              |
| `1004` | 用户不存在或已被删除     | 401              |

#### 购物车模块（7xxx）

| ------ | ------------------------ | ---------------- |

#### 地址簿模块（8xxx）

#### 通用/系统模块（99xxx）

### 微信登录交互流程说明

```markdown
1. 用户打开小程序 → 静默登录（wx.login）→ 后端拿到 openid
2. 后端查询 user 表：
   - 如果 openid 存在 → 直接返回 token（已登录）
   - 如果 openid 不存在 → 创建用户记录（name/avatar 为空），返回 token
3. 前端判断 name 或 avatar 是否为空：
   - 如果为空 → 可提示用户完善个人信息（非强制）
   - 用户可选择头像 + 输入昵称 → 调用"完善信息"接口
4. 后续正常浏览/下单
```

**注意**：完善个人信息为**可选操作**，不强制用户设置。大部分用户只需下单功能即可正常使用。

### 7.3 历史订单查询

- **Path**: `GET /user/order/historyOrders`
- **查询参数**：

| 参数名     | 类型     | 必填 | 说明                                                                               |
|------------|----------|------|------------------------------------------------------------------------------------|
| `page`     | `number` | 是   | 页码                                                                               |
| `pageSize` | `number` | 是   | 每页记录数                                                                         |
| `status`   | `number` | 否   | 订单状态筛选：1=待付款, 2=待接单, 3=已接单, 4=派送中, 5=已完成, 6=已取消, 7=已退款 |

- **响应**: `ApiResponse<PageResult<OrderVO>>`

```typescript
interface OrderVO {
  id: number;                   // 订单ID
  number: string;               // 订单号
  orderDishes: string;          // 订单菜品摘要（展示字符串，如"鱼香肉丝×2, 宫保鸡丁×1"）
  status: number;               // 订单状态
  userId: number;               // 用户ID
  addressBookId: number;        // 地址ID
  orderTime: string;            // 下单时间（ISO 8601 格式）
  checkoutTime: string;         // 结账时间（ISO 8601 格式）
  payMethod: number;            // 支付方式：1=微信，2=支付宝
  payStatus: number;            // 支付状态：0=未支付，1=已支付，2=退款
  amount: number;               // 订单金额
  remark: string;               // 备注
  userName: string;             // 用户名
  phone: string;                // 手机号
  address: string;              // 详细地址
  consignee: string;            // 收件人
  cancelReason: string;         // 取消原因
  rejectionReason: string;      // 拒单原因
  cancelTime: string;           // 取消时间
  estimatedDeliveryTime: string;// 预计送达时间（ISO 8601 格式）
  deliveryStatus: number;       // 配送状态：1=立即送出，0=选择具体时间
  deliveryTime: string;         // 送达时间
  packAmount: number;           // 打包费
  tablewareNumber: number;      // 餐具数量
  tablewareStatus: number;      // 餐具状态：1=按餐量提供，0=具体数量
  createTime: string;           // 创建时间（ISO 8601 格式）
  updateTime: string;           // 更新时间（ISO 8601 格式）
  orderDetailList: OrderDetail[]; // 订单明细列表
}

interface OrderDetail {
  id: number;           // 明细ID
  name: string;         // 菜品/套餐名称（下单时快照）
  orderId: number;      // 订单ID
  dishId: number | null; // 菜品ID（单点菜品时有值，套餐时为null）
  setmealId: number | null; // 套餐ID（单点菜品时为null）
  flavorId: string;     // 口味类型ID列表（逗号分隔，如 "1,2"）
  flavorName: string;   // 口味类型名称列表（逗号分隔，如 "辣度,咸度"）
  flavorVal: string;    // 指定口味值列表（逗号分隔，如 "微辣,少盐"）
  dishCopies: number;   // 菜品数量（单点菜品时使用）
  setmealCopies: number;// 套餐数量（套餐时使用）
  amount: number;       // 金额（下单时快照）
  image: string;        // 图片（下单时快照）
  dishVO?: DishVO;      // 菜品完整信息（仅当dishId不为空时填充）
  setmealVO?: SetMealVO; // 套餐完整信息（仅当setmealId不为空时填充）
}
```

**订单明细展示规则（重要）**：

数据库中的 `order_detail` 表存储逻辑：

- **单点菜品**：`setmealId = null`，`dishId != null` → 一条记录代表一个单点菜品
- **套餐内菜品**：`setmealId != null`，`dishId != null` → 一条记录代表套餐内的某个菜品

后端返回时已做聚合处理：

- **单点菜品**：保持原样，`dishId` 有值，`dishVO` 填充完整菜品信息
- **套餐**：同一套餐的所有菜品已聚合为**一条** OrderDetail 记录
  - `dishId` 设为 `null`（因为代表的是套餐，不是单个菜品）
  - `name` 改为**套餐名称**（从 SetMealVO 中获取）

## 8. 购物车接口 (ShoppingCart)

对应 Java 类：

- DTO：`ShoppingCartDTO`
- Entity：`ShoppingCart`

**说明**：购物车用于临时存储用户选择的商品（菜品或套餐），支持添加、减少数量、修改数量、删除、清空等操作。购物车数据与用户ID绑定，每个用户只能看到自己的购物车数据。

### 8.1 添加商品到购物车

- **Path**: `POST /user/shoppingCart/add`
- **Content-Type**: `application/json`
- **请求体**（对应 `ShoppingCartDTO`）：

```typescript
interface ShoppingCartDTO {
  dishId?: number;        // 菜品ID（菜品和套餐二选一）
  setmealId?: number;     // 套餐ID（菜品和套餐二选一）
  flavorId?: number[];    // 口味类型ID列表（如 [1, 2]）
  flavorVal?: string[];   // 指定口味值列表（如 ["微辣", "少盐"]）
}
```

- **响应**: `ApiResponse<string>`

**业务规则**：

- 如果购物车中已存在相同商品（`dishId`/`setmealId` + `flavorId` + `flavorVal` 完全相同），则数量+1
- 如果是新商品，则插入新记录
- `amount` 由后端自动计算（查询菜品/套餐单价）
- `name`、`image` 由后端从菜品/套餐表中自动填充
- `userId` 由后端从 Token 中获取

**校验规则**：

- `dishId` 和 `setmealId` 至少传一个，不能同时为空
- 如果传了 `flavorId`，必须同时传 `flavorVal`，且两者数组长度必须一致
- 菜品/套餐必须处于起售状态（`status=1`），否则返回错误码 `7002`

**口味字段说明**：前端传递 `flavorId` 和 `flavorVal` 为数组格式（如 `[1, 2]` 和 `["微辣", "少盐"]`），后端接收后拼接为逗号分隔字符串（如 `"1,2"` 和 `"微辣,少盐"`）存入数据库。查询时返回的也是拼接后的字符串格式。

### 8.2 减少购物车商品数量

- **Path**: `POST /user/shoppingCart/sub`
- **Content-Type**: `application/json`
- **请求体**（复用 8.1 的 `ShoppingCartDTO`）
- **响应**: `ApiResponse<string>`

**说明**：减少购物车中指定商品的数量，数量减为0时自动删除该商品。

### 8.3 修改购物车商品数量

- **Path**: `PUT /user/shoppingCart`
- **查询参数**：

| 参数名   | 类型     | 必填 | 说明                       |
| -------- | -------- | ---- | -------------------------- |
| `id`     | `number` | 是   | 购物车记录ID               |
| `number` | `number` | 是   | 目标数量（必须大于0）      |

- **响应**: `ApiResponse<string>`

**业务规则**：

- 直接设置目标数量，后端自动重新计算 `amount`（单价 × 新数量）
- 如果 `number <= 0`，返回错误码 `99001`（参数校验失败）

### 8.4 查看购物车列表

- **Path**: `GET /user/shoppingCart/list`
- **响应**: `ApiResponse<ShoppingCart[]>`

```typescript
interface ShoppingCart {
  id: number;             // 购物车ID
  userId: number;         // 用户ID
  dishId: number | null;  // 菜品ID（单点菜品时有值，套餐时为null）
```

- **口味字段**：`flavorId` 和 `flavorVal` 一一对应，前端可按逗号拆分后配对展示
  - 示例：`flavorId = "1,2"`，`flavorVal = "微辣,少盐"` → 展示为：

    ```markdown
    辣度：微辣
    咸度：少盐
    ```

## 附录A：订单状态说明

| 状态码 | 说明   | 用户端可见 | 说明                             |
|--------|--------|------------|----------------------------------|
| `1`    | 待付款 | ✅         | 订单已创建，等待用户支付         |
| `2`    | 待接单 | ✅         | 已支付，等待商家接单             |
| `3`    | 已接单 | ✅         | 商家已接单，准备中               |
| `4`    | 派送中 | ✅         | 商家已派出配送                   |
| `5`    | 已完成 | ✅         | 订单已完成                       |
| `6`    | 已取消 | ✅         | 用户或商家取消订单               |
| `7`    | 已退款 | ✅         | 用户取消订单且已支付，退款处理中 |

**取消订单规则**：

- 商家未接单前（状态=1或2），用户可取消订单
- 取消后，若已支付，状态变为 `7`（已退款）
- 取消后，若未支付，状态变为 `6`（已取消）
- 商家接单后（状态>=3），用户不可取消订单
